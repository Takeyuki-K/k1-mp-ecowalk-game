## 実ポリシーの測定

### Stage 4：各壁を独立して測定

各壁の手前に置いたロボットを実際に立位で待機させ、その後通常の前進指令で加速した。複数の開始位相を試し、物理ステップの接触を集計した。頭・腕を含むすべての衝突対象形状の保守的な外接範囲が壁の奥まで抜け、途中で接触・転倒がなかった試行のみ成功とした。

| 壁 | 前進指令 m/s | 全身無接触通過 / 試行数 | 成功時の通過区間平均速度 m/s |
|---|---:|---:|---:|
| A | 0.6 | 4 / 16 | 0.572 |
| A | 1.2 | 5 / 16 | 1.159 |
| B | 0.9 | 1 / 15 | 0.872 |
| B | 1.2 | 3 / 15 | 1.158 |
| B | 1.6 | 4 / 15 | 1.492 |
| C | 1.2 | 0 / 13 | — |
| C | 1.6 | 0 / 13 | — |
| C | 2.0 | 0 / 13 | — |
| C | 2.5 | 1 / 13 | 2.395 |
| C | 3.0 | 1 / 13 | 2.733 |

Aは低速でも合わせれば通れるEasy設定。Bは低速での通過機会が少ない。Cは現在の走行ポリシーで通過例を確認できたが、2.0 m/s指令では今回の試行に成功がなかった。**離散的な位相試行の結果であり、厳密な最低速度の証明や、全位相・全経路での通過不能の証明ではない。** 高い速度だけで通れるわけでもない。

平地で1.2 m/sを指令すると、発進から1秒では実速度約0.05 m/s、2秒では約0.90 m/s、3〜5秒では約1.13〜1.17 m/sだった。2.5 m/s指令では2秒で約2.31 m/s、3〜5秒で約2.46〜2.55 m/s。これらは特定の初期姿勢の測定であり、停止後の姿勢や旋回によって変わる。人間評価では加速前の安全距離も確認する必要がある。

## 接触と挟まれ時の保護

単体物体を用いたMuJoCo試験で、閉じた壁への実接触と進行阻止を確認。

障害物は指定軌道に従うmocap物体で、接触で押し返される有限質量の物体ではない。左右の扉にロボットを意図的に挟んだまま計算し続けると、大きなめり込みが生じた。このためStage 4では、実接触のめり込みが保護閾値を超えると `collision` の失敗として試行を停止する。画面は「接触により停止」となり、リトライできる。軽い接触の減点は維持する。

保護テストでは深い接触を検知して停止し、その後の操作で状態が進まないこと、新規リトライで解除されること、有限な状態を維持することを確認した。MuJoCoの柔らかい接触を使うため、数学的に完全な非貫通や、あらゆる姿勢・速度での安定性は保証していない。

## 再現手順

リポジトリ直下、セットアップ済み環境で実行する。開発テストのソース・内部フィクスチャは後続のAIプレイヤーに公開しない。

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest tests -q
node tests/test_controls.cjs
NODE_PATH=/tmp/k1-ui-check/node_modules node tests/test_ui.cjs
# 実ポリシーによる位相走査・既存コース（数分）
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/validate_vnext.py
```

DOMテスト用jsdomの導入手順はREADMEを参照。外部pytestプラグインの読み込みを無効化する設定は、この環境のROSプラグインによる依存エラーを避けるため。HTTPテストにはlocalhostソケットが使用できる環境が必要。vendorのモデルがない環境では実ポリシー統合テストだけを明示的にskipする。
